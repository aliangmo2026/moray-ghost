# v0.6 设计草案：CDP 浏览器接管 / 拖拽滚轮轨迹 / 驾驶舱动作日志

> **文档来源声明**：本稿由 ghost 侧基于 v0.5.0 平台化落地代码与 dsh-pilot 竞品
> 能力对照新起草，作为讨论底稿；确认后再动代码。现状基线：commit `5edad40`
> （v0.5.0 + 鼠标动作审计修复）。

## 0. 目标与非目标

- **目标**：① CDP 协议接管本地 Edge/Chrome（网页元素级操作，替代网页上的 OpenCV 找图）；
  ② 原生 drag/scroll 支持平滑轨迹（CAD/Blender 场景），宏录制记录完整轨迹数组；
  ③ Dashboard 升级驾驶舱：实时动作日志（含执行后微缩截图）。
- **非目标**：不做视觉推断、不替代主仓规划、不引入任何云端依赖；新增通道
  全部纳入现有安全管道与审计体系（这是对竞品"无防呆像素操作"的核心差异化）。

## 1. 总体架构增量

```
主仓 (D:\MoRay) ── 本机 HTTP + X-Ghost-Token ──► ghost
   原生通道: controller.run_action  click/move/type/hotkey + ★drag/scroll
   网页通道: ★browser_driver.py (playwright connect_over_cdp)
                    └──► 本地 Edge/Chrome (--remote-debugging-port=9222)
   共享底座: input_audit 审计 · 前后截图 · ACTION_LOCK 串行 · 冻结门禁 · 驾驶舱事件总线★
```

- 两个输入通道（native / cdp）在 `controller.run_action` 汇合：同一把串行锁、
  同一条审计线、同一个冻结位；`input_audit` 增加 `channel` 字段区分来源。

## 2. CDP 浏览器接管（`app/core/browser_driver.py`）

### 2.1 依赖选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **playwright**（`connect_over_cdp`） | 元素定位器成熟（role/text/css/placeholder）；API 稳定、社区大；连接模式不捆绑浏览器 | pip 包约 45MB（含 node driver） | **推荐** |
| pychrome（纯 CDP websocket） | 体积小、零封装黑盒 | DOM 查询/点击序列全要手写，维护成本高 | 备选 |

选定 **playwright**：只用 `connect_over_cdp("http://127.0.0.1:9222")` 连接模式，
**不执行 `playwright install`**（绝不下载捆绑浏览器），进程内不 spawn 浏览器。

### 2.2 信任边界与生命周期

- ghost **不自动拉起浏览器**：被控浏览器必须由用户/主仓显式以
  `--remote-debugging-port=9222` 启动（保持"绝不做用户没要求的事"）。
- 新配置 `BROWSER_CDP_URL`，默认 `http://127.0.0.1:9222`；**仅允许 127.0.0.1/localhost**
  （硬编码白名单，防 SSRF 面扩张）。
- 连接失败 → 503 `BROWSER_NOT_CONNECTED`（语义化失败，绝不静默降级为视觉方案）。

### 2.3 API

`POST /api/ghost/browser/action`（走 token 中间件 + 冻结门禁，与 execute_action 同级）：

```jsonc
{
  "op": "click|dblclick|type|scroll|hover|drag|press_key",
  "tab": {"url_contains": "example.com"},   // 约束在哪个 tab 上操作；缺省=活跃 tab
  "selector": {"by": "role|text|css|placeholder", "value": "提交", "nth": 0},
  "text": "...", "dy": -300, "points": [[x,y],...]   // 按 op 取用（页内 CSS 像素）
}
```

- 响应：命中的 element bounding box、tab id、页内前后截图（`Page.captureScreenshot`，
  非全屏 mss）、elapsed_ms。
- 定位失败 → 409 `ELEMENT_NOT_FOUND`（带候选匹配数），多候选 → 409 + 列表，
  绝不"猜第一个"。

### 2.4 安全管道对齐（防呆不绕过）

- CDP 输入不经过 OS 光标，pyautogui Fail-Safe 不适用 → 改用等价防线：
  ① **冻结门禁**：`task_queue.is_frozen()` → 503（与 execute_action 同级）；
  ② **会话白名单**：只允许操作 CDP 会话内的 tab，绝不触碰其他窗口/进程；
  ③ **审计沿用**：每次调用记 `input_audit channel=cdp`（op/tab/selector）；
  ④ **串行沿用**：与原生动作共用 ACTION_LOCK（审计与状态一致性需要）。
- 任务/宏步骤可引用 browser action（`kind: "browser"`），Agent 隔离语义透明生效。

## 3. 拖拽与滚轮（drag / scroll + 平滑轨迹）

### 3.1 动作 schema（execute_action 扩展）

```jsonc
// action=drag：points 缺省时由起终点 + duration_ms 插值生成轨迹
{"action": "drag", "x": 100, "y": 200, "x2": 800, "y2": 640,
 "duration_ms": 900, "points": null, "monitor": 1, "hwnd": 123}
// action=scroll：smooth 时分片滚动（CAD/Blender 缩放手感）
{"action": "scroll", "x": 600, "y": 400, "dy": -480, "smooth": true, "hwnd": 123}
```

### 3.2 执行语义（安全管道内，`backend` 新原语）

- drag：`mouseDown` → 逐点 `moveTo`（点间隔 ≤16ms，相邻点位移限幅防瞬跳）→
  `mouseUp`；全程在 ACTION_LOCK 内。
- **中途 Fail-Safe**：每个轨迹点检查 `_in_corner(current)` → 命中立即 `mouseUp`
  + FailSafeTriggered（绝不留"按住"状态）；`finally` 强制释放鼠标键与修饰键
  （沿用 release_all_modifiers 的"绝不泄漏"模式，新增 `release_pointer_buttons`）。
- 漂移校验：起点沿用 DRIFT_LIMIT_PX；终点复核落点归属（带 hwnd 时）；
  轨迹全程实际坐标写入审计（`cursor_after` 升级为轨迹数组摘要）。
- 轨迹点上限 2000（超限按弧长降采样），payload 防膨胀。
- scroll：先 moveTo (x,dy) 落点，再 `pyautogui.scroll` 分片（smooth=10~20 片）。

### 3.3 宏录制与重放

- recorder 对 drag 步原样记录 `points` + 相对时间戳（主仓录制期下发什么记什么）；
  重放按时间戳复现节奏（总时长 clamp 0.1~10s）。
- scroll 步记录 `dy/smooth`；heal 接口对 drag/scroll 步沿用锚点 relocate 机制。
- steps_json 新 kind 向后兼容：旧宏零影响；DB 无需迁移（steps_json 为 JSON blob）。
- backlog（本期不做）：录制会话内 mouseDown~mouseUp 期间 30Hz 后台采样
  `GetCursorPos` 自动生成轨迹（应对主仓直接操控真鼠标的录制流）。

## 4. 驾驶舱：实时动作日志（Action Log）

### 4.1 后端

- 内存环形缓冲 `action_log`（deque maxlen=200，进程重启即清，与任务注册表同策略）：
  `{ts, agent_id, channel(native|cdp), action, coords/selector, ok|error,
    http_status, task_id?, thumb}`。
- 写入点：`run_action` 成功/失败/异常三路径 + browser_driver（一处汇点，无遗漏）。
- `GET /api/ghost/actions/recent?limit=50`：只读，与 /screenshot 同级免 token
  （面板数据源；信息量与全屏截图同级）。
- `GET /api/ghost/actions/thumb/{name}`：**basename 白名单**（仅 SCREENSHOT_DIR
  内已知文件名，规范化后校验前缀，防路径穿越），返回 after 截图的 96px 缩略。

### 4.2 前端（Dashboard 卡片）

- 新卡片"实时动作日志"：1s 轮询 recent；每行 = 时间 · agent · 动作 · 坐标/选择器 ·
  状态徽标 + 64px 缩略图（点击看原图）；自动滚动，显示最近 30 条。
- 与急停联动：frozen 时横幅已有的基础上，冻结期被拒动作（503）也入账滚动——
  "它在干什么、为什么没干成"全程可见。
- 轮询开销：recent 为纯内存序列化，<5ms，与现有 1s state 轮询合并为同一节拍。

## 5. 安全红线清单（新功能逐条对照）

| 红线 | 原生通道 | CDP 通道 |
|---|---|---|
| 冻结门禁 (emergency stop) | 不变 | 同级生效 |
| 前台门禁 / 落点归属 | 不变（drag 终点复核） | 会话内 tab 白名单承担同等职责 |
| Fail-Safe 角落 | drag 逐点检查 + 强制释放鼠标键 | 不适用（无 OS 光标），靠冻结+白名单 |
| 全量审计 | input_audit + channel 字段 + 前后截图 | 同左（页内截图） |
| 串行执行 | ACTION_LOCK | 同一把锁 |
| 依赖面 | 不变 | 仅本地 CDP 连接，禁 bundled browser |

## 8. 风险与开放问题

- playwright 在 DPI 感知进程内仅作网络客户端（connect 模式无 GUI），与
  SetProcessDpiAwareness(2) 无冲突；实测验证列入 M2 验收。
- 开放①：CDP 通道是否允许发起新 tab/导航（本期仅操作已有 tab，导航入 backlog）。
- 开放②：Action Log 是否需要落盘持久化（本期内存态，与任务注册表同策略）。
- 开放③：主仓录制流是否直连 browser action（M2 后与主仓侧对齐 schema）。
