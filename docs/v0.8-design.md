# v0.8.0 MCP 多模态感知底座 · 设计结构（vl_driver + mcp_server）

> 状态：已实施（本文档与代码同步）。
> 前提红线：不破坏既有 CDP、安全门禁（令牌 / 能力白名单 / 黑名单 / 熔断 / 硬超时 /
> 看门狗 / 审计）——MCP 只是**又一个走了 HTTP+Token 通道的客户端**，服务端门禁
> 在此模式下 100% 原样生效。

## 0. 总体数据流

```
AI Agent（任意 MCP 客户端：Claude / 自研 Agent / …）
   │   MCP Stdio（JSON-RPC 2.0，newline-delimited；mcp SDK 2.x MCPServer）
   │   启动时由 Agent 注入身份环境：GHOST_TOKEN / GHOST_AGENT_ID / GHOST_CAPABILITIES
   ▼
mcp_server.py（根目录，Stdio 常驻；只做协议翻译 + 路由，不做任何输入执行）
   │   HTTP 127.0.0.1:8030 + X-Ghost-Token + X-Agent-Id + capabilities
   │   （与 sdk/GhostClient 完全同通道 → 中间件鉴权 → 控制器安全管道）
   ▼
Ghost API：/screenshot · /execute_action · /task · /browser/action …
   │   安全管道：令牌 → 环境门禁 → 冻结/熔断/硬超时 → 能力令牌 →
   │   UAC/窗口/键盘黑名单 → 落点归属 → 前后审计截图 → JSONL 审计
   ▼
路由分流（vl_driver.resolve_channel）
   ├─ URL 样式 / Edge·Chrome 窗口 → CDP 通道（browser_driver，by=text 选择器）
   └─ 原生桌面窗口            → VL 通道（vl_driver 定位控件 bbox 中心 → click）
```

## 1. `app/core/vl_driver.py` — 本地多模态感知驱动

### 1.1 统一输出契约

```json
{
  "ok": true,
  "backend": "native | llama | mock",
  "window": {"hwnd": 123, "title": "..."},
  "controls": [
    {"text": "保存成功", "type": "button", "bbox": [x, y, w, h], "center": [x, y]}
  ],
  "elapsed_ms": 42
}
```

- 坐标一律**物理像素、全屏坐标系**（与 /screenshot 全尺度、execute_action 同一约定）。
- `type` 启发式：button / input / text / menu / unknown（按 Win32 类名 + 样式）。

### 1.2 接口

| 函数 | 语义 |
|---|---|
| `analyze(monitor=1, hwnd=None, window=None, backend="auto")` | 截图/枚举 → 控件列表 |
| `find_control(result, text, match="exact\|contains")` | 精确匹配控件；0 命中 → `VLElementNotFound`；多命中 → `VLAmbiguous`（**绝不猜**，与 CDP ELEMENT_AMBIGUOUS 同哲学） |
| `resolve_window(window=None)` | window=None → 前台窗；URL 字符串 → (cdp, url)；子串 → 可见顶层窗（0→NOT_FOUND, >1→AMBIGUOUS） |
| `resolve_channel(window=None, hwnd=None)` | 返回 `"cdp"` / `"native"`：URL 样式或 Edge/Chrome 窗口 → cdp，其余 → native |

### 1.3 backend 策略（`GHOST_VL_BACKEND=auto|native|llama|mock`）

| backend | 依赖 | 定位方式 | 用途 |
|---|---|---|---|
| `ocr`（轻量级本地视觉，默认主力） | `rapidocr-onnxruntime` + `onnxruntime`（PP-OCR ONNX 模型随包内置） | 全尺度/窗口 ROI 截图 → 文本检测+识别 → 文本 bbox（物理像素） | **"看像素"的真实感知**：Tk 等自绘控件的标签文本（win32 枚举拿不到，实证 Tk Button 窗口文本为空） |
| `native`（零依赖） | win32 | `EnumChildWindows + GetWindowText + GetWindowRect`（类名→类型启发式），顶层窗自身也是一条控件 | 最快几何枚举；文本仅限真 Win32 控件（有窗口文本的） |
| `llama`（真实 VL 语义级） | `llama-cpp-python` + `GHOST_VL_MODEL_PATH`（GGUF，如 Qwen2-VL-2B / MiniCPM-V） | `screen_mss.grab` 全尺度截图 → chat(mm) JSON → bbox clamp + monitor origin 换算 | 复杂/语义级 UI 理解（接入真实模型阶段的主通道） |
| `mock` | 无 | `GHOST_VL_MOCK_JSON` 夹具 | 纯协议联调 |
| `auto` | — | llama 可用（import 成功 + 模型路径存在）→ llama；否则 ocr 可用 → ocr；否则 native | 生产默认 |

- 任一后端不可用时**如实降级并回显真实 backend 字段**，绝不冒充模型输出。
- 引擎懒初始化、进程内单例缓存（OCR/LLM 句柄不重复加载）。
- **收口位置**：感知只在 Ghost 服务端执行（`POST /api/ghost/vl/analyze`，需 token，
  冻结期可用——只读）：抓屏走 screen_mss 单一 capture 线程；模型进程内只加载一次
  （不随每个 MCP 客户端复制）。

### 1.4 路由分流规则

```
window 为空                → native（前台窗口，确定性默认）
window 以 http(s):// 开头   → cdp（tab url_contains=window）
window 命中 Edge/Chrome 顶窗 → cdp（进程判定 msedge/chrome/msedgewebview2）
其余 window 子串            → native（限定该窗口分析与点击）
channel 参数显式给定         → 一律覆盖 auto 判定
```

## 2. `mcp_server.py` — MCP Server 标准化封装（根目录）

### 2.1 进程与身份模型

- 官方 `mcp` SDK 2.x：`mcp.server.mcpserver.MCPServer`，`run(transport="stdio")`。
- 由 Agent 以 stdio 拉起；**身份在启动时从环境注入，tool 参数永远无法覆盖白名单**：
  - `GHOST_TOKEN`（缺 → 启动即拒，退出码非 0：拒绝匿名网关）
  - `GHOST_AGENT_ID` → `X-Agent-Id`
  - `GHOST_CAPABILITIES`（JSON 数组，如 `["notepad.exe"]`）→ 所有输入类请求的
    `capabilities.allowed_windows`（**per-call 不可改宽**，`execute_task` 会覆盖
    payload 自带的同名字段）
- token 只从环境/.env 读取（与 SDK 同语义），不落盘、不打印、不进错误详情；
- 服务地址固定 `127.0.0.1:8030`（与全套测试/单实例约定一致，请求点内联字面量）。

### 2.2 MCP Tools

| Tool | 入参 | 行为 | 安全落点 |
|---|---|---|---|
| `analyze_screen` | `monitor=1, window?, backend="auto"` | `POST /vl/analyze`（服务端跑 vl_driver）→ 控件 JSON | 只读（需 token；冻结期可用；模型不随客户端复制） |
| `click_element` | `text, window?, channel="auto", match="exact", settle=0.3` | **路由**：cdp → `POST /browser/action`（selector by=text）；native → analyze+find → `POST /execute_action`（x,y=中心, hwnd, capabilities） | 令牌/能力令牌/UAC/窗口黑名单/落点归属/熔断/硬超时全链生效；AMBIGUOUS/NOT_FOUND 绝不猜 |
| `type_text` | `text, hwnd?, settle=0.3` | `POST /execute_action`（type；带 hwnd → 前台门禁 409） | 键盘黑名单、能力令牌、前台门禁、硬超时；建议流程 click_element 先聚焦 |
| `execute_task` | `task_payload`（steps/goal/…）, `wait=true, timeout=60` | `POST /task`（capabilities 强制 env）→ `start` → 可选轮询至终态 | 服务端 capabilities 校验、状态机、冻结门禁不变 |

- 所有 tool 错误一律返回结构化 `{"ok": false, "error": "...", "detail": "..."}`
  （401/403/409/429/408 原样透传 error code），**绝不让协议层吞掉安全拒绝**。

### 2.3 与既有系统的关系

- 复用 `vl_driver.resolve_channel` 的 CDP 分支 → 原有 browser_driver、冻结门禁、
  `ELEMENT_AMBIGUOUS` 语义原样继承；
- 不新增任何免 Token 端点；`mcp_server.py` 自身**不监听任何端口**（纯 stdio）。

## 3. 测试计划 `scripts/test_v08_mcp_vl.py`

1. 起 Ghost 服务（drain 管道）；
2. 自建 Tk 靶窗（按钮「保存成功」+ Entry + 标题回显键入内容；stdout 握手 hwnd/坐标）；
3. MCP Client（stdio）：`initialize` → `tools/list` 恰为 4 个且 schema 完整；
4. `analyze_screen` → 靶窗控件在列表中、按钮 bbox 中心与真实位置一致（误差 ≤2px）；
5. `click_element("保存成功")` → 真实点击 → 靶窗标题变化；
6. `type_text(hwnd)` → Entry 键入 → 标题回显文本（硬绑定 `<Key>`）；
7. `execute_task(wait 步骤)` → done；
8. 门禁透传：错 token 拉起 → click 拒绝（UNAUTHORIZED）；错 capabilities 拉起 →
   点击不在白名单的进程 → 403 CAPABILITY_DENIED；`window="https://…"` → 走 CDP 分支
   （未连调试端口 → 浏览器通道错误，证明路由生效）；
9. 既有 314 项回归保持全绿。

## 4. 依赖

- `mcp==2.3.0`（官方 SDK，Stdio；2.x 命名：FastMCP → `MCPServer`，模型字段蛇形）；
- `rapidocr-onnxruntime==1.4.4` + `onnxruntime==1.31.0`（ocr 后端；安装用
  `--no-deps` 主包 + 手动补依赖，保留既有 `opencv-python-headless` 共用 cv2）；
- `llama-cpp-python==0.3.36`（真实 VL 后端）——Windows 安装走官方 CPU wheel 索引
  `--extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu`；
  源码编译需短 TMP（260 字符长路径）+ MSVC；
- 模型文件（GGUF + mmproj）由部署方经 `GHOST_VL_MODEL_PATH` 提供，仓库不含权重；
- 打字注入：ASCII 用 `keyboard.write`（本机实证 IME 会把 pyautogui 字母打成
  VK_PROCESSKEY；keyboard 送规范 VK+扫描码），失败回落 pyautogui.write。
